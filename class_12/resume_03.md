# Guia Docente: Iterative Frontend Development with AI

Este documento adapta el modulo de desarrollo frontend iterativo.
El foco es reemplazar la busqueda de "resultado perfecto al primer intento"
por un proceso por fases que mejora calidad y velocidad de entrega.

## 1. Objetivos de aprendizaje

Al finalizar la clase, el estudiante deberia poder:

- Entender por que iterar supera intentar perfeccion inmediata.
  Como explicarlo: comparar tiempo y calidad entre enfoque monolitico vs incremental.
- Aplicar mentalidad de construir en lugar de solo generar.
  Como explicarlo: guiar decisiones activas en cada paso, no aceptar salidas sin criterio.
- Ejecutar el algoritmo del pintor en frontend.
  Como explicarlo: construir por capas: estructura, contenido y estilo.
- Implementar fase 1 con estructura solida.
  Como explicarlo: definir layout, regiones y flujo responsive antes de pulido visual.
- Implementar fase 2 con contenido y componentes.
  Como explicarlo: completar textos, datos y componentes funcionales en jerarquia correcta.
- Implementar fase 3 con estilo y refinamiento.
  Como explicarlo: ajustar color, tipografia y detalle sin romper la base estructural.

## 3. Guion sugerido para clase online (30 minutos)

### Bloque A (6 min): Cambio de mentalidad

- Iterar como estrategia de calidad.
  Como explicarlo: mostrar que corregir sobre base estable es mas rapido que rehacer completo.
- Camino de menor resistencia.
  Como explicarlo: empezar por lo esencial y desbloquear progreso temprano.
- Construir vs generar.
  Como explicarlo: evaluar cada salida de IA y ajustar direccion en lugar de aceptar todo.

### Bloque B (8 min): Algoritmo del pintor aplicado

- Fase 1: estructura primero.
  Como explicarlo: definir contenedores, zonas y responsividad base sin detalles visuales.
- Fase 2: agregar contenido.
  Como explicarlo: incorporar componentes, copy y datos reales de forma incremental.

### Bloque C (8 min): Estilo y pulido

- Fase 3: estilo y pulido.
  Como explicarlo: aplicar sistema visual sobre una arquitectura ya validada.

### Bloque D (8 min): Lenguaje de feedback tecnico

- Hablar de diseno con precision tecnica.
  Como explicarlo: transformar feedback subjetivo en observaciones sobre jerarquia, espaciado y contraste.
- Patrones de retroalimentacion reutilizables.
  Como explicarlo: usar frases accionables como "ajusta el padding", "incrementa contraste", "alinea grid".
- Evitar solicitudes vagas.
  Como explicarlo: reemplazar "hazlo mas bonito" por cambios medibles y verificables.

### Bloque E (4 min): Evaluacion y dominio del proceso

- Evaluacion de conocimiento.
  Como explicarlo: comprobar que el estudiante distingue fase, objetivo y criterio de calidad.
- Criterio de finalizacion.
  Como explicarlo: cerrar cuando cumple estructura, contenido, consistencia visual y feedback tecnico aplicado.

## 4. Errores frecuentes y correccion

- Error: intentar resolver todo en un solo prompt.
  Correccion: dividir en fases y validar salida por etapa.
- Error: pulir visual antes de estructura.
  Correccion: congelar estilos hasta validar layout y flujo.
- Error: no definir checkpoints intermedios.
  Correccion: establecer criterios de aceptacion por cada fase.
- Error: cambiar demasiadas variables en cada iteracion.
  Correccion: modificar un aspecto por ciclo para aislar mejoras.

## 5. Cierre para sesion

- Mensaje clave: la iteracion disciplinada produce frontend mas estable y mantenible.
- Resultado esperado: estudiante capaz de construir interfaces por capas con apoyo de IA.
- Siguiente paso: integrar comunicacion efectiva + especificacion visual + iteracion en una sesion completa de 90 minutos.
